Scalar prefetch and shrunk grids

How a mask predicate becomes an index_map. The API, the two table constructions, the kernel skeleton, and the numbers each half actually buys.

The one-line version

Block skipping is copy elision driven by a table. No new pipeline, no sparse grid type. An index_map reads a prefetched SMEM table and returns the same block index twice in a row; the consecutive-index elision rule does the rest.

API

Replace grid= with grid_spec=. Prefetched arrays go to SMEM before the pipeline starts and take no BlockSpec.

grid_spec = pltpu.PrefetchScalarGridSpec(
    num_scalar_prefetch=2,          # first 2 call args -> SMEM
    grid=(n_q, grid_width),
    in_specs=[pl.BlockSpec((bq,  head_dim), q_map),
              pl.BlockSpec((bkv, head_dim), kv_map),
              pl.BlockSpec((bkv, head_dim), kv_map)],
    out_specs=pl.BlockSpec((bq, head_dim), q_map))

pl.pallas_call(kernel, grid_spec=grid_spec, out_shape=…)(
    kv_next, run, q, k, v)         # prefetch args first

Argument order is fixed in both signatures — get it wrong and the failure is a shape error a long way from the cause:

index_map(*grid_indices, *prefetch_refs)
kernel(*prefetch_refs, *input_refs, *output_refs, *scratch_refs) 
def q_map(i, j, kv_next_ref, run_ref):
    del j, kv_next_ref, run_ref          # ignores the fast axis -> resident
    return (i, 0)

def kv_map(i, j, kv_next_ref, run_ref):
    del run_ref
    return (kv_next_ref[i, j], 0)        # the lie

The two tables

Names and semantics are splash_attention's (splash_attention_mask_info.py, MaskInfo). Both are [heads_or_shards, n_q, grid_width] integers.

TableEntryRead by
block_mask0 dead · 1 partial · 2 fullthe kernel body

mask_nextindex into partial_mask_blocksthe kernel body

block_mask is lesson 01's trichotomy. Same three states, same two consequences — see Block-skipping arithmetic.

0 → do not fetch, do not compute  ·  1 → fetch, compute, mask elementwise  ·  2 → fetch, compute, skip the mask 
is_nonzero      = block_mask_ref[h, i, j] > 0    # should_run
should_not_mask = block_mask_ref[h, i, j] != 1   # it is a 2
next_j          = data_next_ref[h, i, j]

_next_nonzero, splash_attention_kernel.py. Construction is block_mask = where(is_full, 2, where(is_empty, 0, 1)) in splash_attention_mask_info.py, computed host-side from the materialised mask with .all() and .any() per block.

data_next, unshrunk

At column j: the next live column at or after j; if there is none, the last live column at or before it. Dead columns therefore repeat a neighbour's index, and the copy is elided.

data_next, shrunk

Per row, left-pack the live columns; pad every row out to grid_width = max live per row — "this avoids having jagged rows". Padding entries are index 0 with block_mask = 0, not a repeat of the previous index. So a padded step still resolves an index_map and may cost a transfer.

grid_width = fwd_mask_info.data_next.shape[-1]
grid = (num_q_heads, q_seq_len // bq, grid_width)

Kernel skeleton

def kernel(kv_next_ref, run_ref, q_ref, k_ref, v_ref, o_ref):
    i, j = pl.program_id(0), pl.program_id(1)

    @pl.when(j == 0)                          # first inner step: initialise
    def _():
        o_ref[...] = jnp.zeros_like(o_ref)

    @pl.when(run_ref[i, j] == 1)              # dead / padded steps do nothing
    def _():
        kv = kv_next_ref[i, j]                # positions must come from the TABLE,
        …                                     # not from j — j is a lie now
        o_ref[...] += …
The trap

Once index_map lies about j, every use of j as a position is wrong. The elementwise mask needs real key indices, and those are data_next[i][j] * bkv + iota, never j * bkv + iota. This is the error that produces a kernel which is fast, runs clean, and is silently wrong for exactly the rows the window clips.

The load-once property, and its precondition

When W ≤ bkv each row's live set is {i−1, i}, the flattened kv index sequence never decreases, elision crosses the row boundary, and every kv block is loaded exactly once for the whole layer. This is a property of the geometry, not of block skipping.

Row 2: widening the window past the block breaks the ordering — the sequence steps backwards at each row boundary. Row 3: halving B costs 20 loads for 8 blocks. The counting sheet already said halving B quadruples the grid; it also destroys the load-once property.

Row 4 checks against session 1's arithmetic: live tiles R·m − m(m−1)/2 = 64·2 − 1 = 127, and the kernel computes 127. The spare step is row 0's padding.

Invariants worth checking

  • Output revisits stay consecutive. Shrinking removes steps inside a row and never permutes i, so an output block is revisited grid_width times in a row. Lesson 03's accumulator rule survives; RevisitMode.ANY is not needed.
  • o_ref is not the accumulator in splash_attention. The running sum is o_scratch at f32, rescaled each step; o_ref takes one store on the last inner step, normalised and cast. Residency is spent on skipping write-backs, not on accumulating.
  • Block skipping never removes the mask. At W = B there are no 2s at all — no W-wide block fits inside a W-wide band — so every loaded block is masked elementwise.
  • Nothing here is evidence about a v5e. The counts are from CPU interpreters. Whether elision is contractual on the Mosaic path is an open gap in RESOURCES.md.
