Reference sheet

Block-skipping arithmetic

Everything needed to decide, at trace time, which tiles a windowed attention kernel must load — and how much it costs to get the block size wrong.

Mask conventions

As implemented in reference.py. Query q, key k, window W:

causal   k ≤ q   ·   windowed   k > q − W

So query q sees keys [q−W+1, q] — W keys including itself, not W+1. A global layer is the same formula with W = ∞. Decode adds offset to q; nothing else changes.

The tile predicate

Tile spans queries [qlo, qhi], keys [klo, khi]. Two integer comparisons, no loop:

live ⟺ qhi ≥ klo  and  qlo − khi ≤ W − 1
full ⟺ khi ≤ qlo  and  qhi − klo ≤ W − 1
partial ⟺ live and not full  ·  dead ⟺ not live

Why it is only two comparisons. Over the tile, the diagonal d = q − k sweeps the contiguous interval [qlo−khi, qhi−klo] — contiguous because a rectangular tile is a dense product of two contiguous ranges. The mask is the band 0 ≤ d ≤ W−1. live asks whether the two intervals intersect; full asks whether the band contains the tile's interval. Same two intervals, two different relations.

The minimum sits at (qlo, khi) because d grows with q and shrinks with k. Derive the corner from the sign rather than memorising it.

Hull relaxation is sound, not exact

Testing endpoints means testing the hull [dmin, dmax] in place of the set of d values actually achieved. The hull can only be larger, so for a mask that is not a band — where the achieved set may have holes — live can false-positive (a tile loaded that was dead: one wasted DMA) and full can false-negative (an elementwise mask applied that was a no-op: one wasted pass). Both errors cost work; neither costs correctness. Contiguity buys exactness, not validity. Hull-relaxing an unfamiliar mask is always safe — the only question is how much work it wastes.

Verified

Checked exhaustively against reference.attention_mask(): 16,464 tiles, N ∈ {512, 1024, 2048} × W ∈ {128, 256, 512, ∞} × block sizes {64, 128, 256}. Zero mismatches.

Counting formulas

Square blocks of size B, with B | N and B | W. Let R = N/B rows and m = W/B + 1 live tiles per unclipped row.

pairs keptN·W − W(W−1)/2N(N+1)/2

total tilesR²R²

The subtracted triangle in both live-tile formulas is the clipping at the start of the sequence, where a query row has fewer than m blocks behind it.

Trap

The Gemma 3 technical report says the sliding window was reduced "from 4096 to 1024". That describes the larger models. The 1B ships sliding_window: 512. For per-model numbers, the config is the authority, not the paper.

Cost of a pair

FLOPs = 4 · pairs · head_dim · num_heads

Two matmuls per pair — QKT and PV (the post-softmax probabilities times V) — at 2·D FLOPs each. Matches attention_flops() in shapes.py.
